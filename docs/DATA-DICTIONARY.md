# 检测区间与复检

采样日期选择限量标准[start,end)，不使用报告出具日。同产品同残留项目在采样日须恰有一条有效标准，方法须在适用范围内。浓度统一mg/kg，ug/kg与ppb乘0.001，ppm等于mg/kg。检出限LOD必须大于0。

定量值以[value,value]记录，低于LOD的定量值拒绝。ND或<LOD以[0,LOD)记录，<后的数值必须等于报告LOD。区间上界≤限量为PASS，下界>限量为FAIL，其余UNCERTAIN。<0.01相对0.005限量为不确定，不能当零。

复检relation指向原报告，必须同样本、同批次、同产品、同残留项目、同方法、同采样日，报告日严格更晚。引用环、悬空引用与异样本引用隔离。每样本/项目只允许一个原始报告根。有效复检按reported、version取最新；并列结果矛盾拒绝。其他残留项目不因复检被覆盖。批次按FAIL>UNCERTAIN>PASS取最高风险等级。

## 通用采信约定

CSV按UTF-8 BOM、UTF-8、GB18030回退，保留逻辑记录结束行号；引号内换行由CSV解析。重复表头单独计数，列数不齐隔离。编码与ID按字符串保形。缺失哨兵为 `-`、`N/A`、`NULL`、`未知` 与空串；不得作为零。数值先NFKC归一、去千分位，再用Decimal。日期采用ISO；时间必须带偏移并转UTC。空文件、全空行、仅表头分别返回EMPTY_FILE、BLANK_FILE、HEADER_ONLY。

重复键为(id,version)，完全相同行去重；同键内容冲突则整组隔离，不取最后一行。行数对账：输入=采纳+隔离+空行+重复表头+完全重复。运行幂等键由输入字节、参数与规则版本计算。

同一报告ID的多个版本先选最高version，再构建复检引用链；历史版本留作采信证据，不重复参与最终项目判定。

## 台账重传

上游重发整份台账时，以“上一份已发布批次”为基准逐份裁决，判据围绕样本/项目结论槽位：

| 变更 | 判定条件 | 可发布批次 |
|---|---|---|
| NEW | 新报告ID，占据新槽位 | 进入批次 |
| EVIDENCE | 新报告ID，但槽位已有别的结论 | 仅作证据，不改结论 |
| UNCHANGED | 与已采信报告内容完全一致 | 沿用，不计增删 |
| CORRECTED | 同ID同version但内容变化 | 挂起，沿用已采信结论 |
| REVISED | 同ID换version | 挂起，沿用已采信结论 |
| WITHDRAWN | 已采信报告在新台账中消失 | 挂起，旧结论保留 |
| SUPERSEDED | 新报告沿relation显式指向已采信报告 | 新结论进入批次，旧报告留档标记_retired |
| CONFLICTED | 新报告占据已有槽位但未显式指向已采信报告 | 挂起，旧结论保留 |
| REJECTED | 该行未通过采信/映射/选版/换算校验 | 不进入批次 |

比较内容时只比报告身份字段，note自由文本不参与。挂起项以 `held` 标记并可经 `held_lines` 回到源行；已采信报告永不删除，逐条留在登记簿 `register` 中。批次判级、样本计数与封存一律读裁决后的 `accepted`，不读原始计算清单。

被挂起的更正/换版/撤回默认沿用旧结论。如经人工复核确认可以换版，在提交时用 `parameters.accept` 列出报告ID（或 `parameters.accept_all` 为真）显式放行；放行逐条记入 `confirmed`，仍保留源行与基准行凭据，不会变成无痕覆盖。从未成为最终结论的历史证据被改写只留档、不进入 `held`，避免虚增复核量。

处理中断或任一裁决无法与源台账核对（`decided`/`preserved`/`batch_accounted` 不成立）时整批回退到旧版发布，不推进发布指针。发布指针只在批次对账相符、重传裁决可发布且封存可用时前移；发布内容按可出证内容指纹去重，同一台账重跑不重复发布。封存 CSV 同时留档本次重传台账与上一份已发布台账的原始字节（base64 + sha256），两份均可逐字节复核。
